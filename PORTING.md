# Porting notes

One row per component where the Twig → Astro port needed a decision.

| Component | Twig construct                                                                                                 | Astro decision                                                                                                                                                                                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paragraph | `{{- content -}}` (no `\|raw` in the twig, but the doc header types `content` as `[string,null]` HTML-bearing) | Rendered with `set:html` per R2's "content / html-bearing string props" rule, not a plain text child. No `allow_html` prop exists upstream, so none was added — the task brief's illustrative example included one that does not match the real Twig.                                                            |
| Paragraph | `no_margin: [boolean,null]`                                                                                    | Astro prop `noMargin?: boolean \| null`, default `false`; only appends `ct-paragraph--no-margin` when true. Not exercised by an upstream snapshot, so parity for this branch rests on the class-list logic mirroring the twig, not a captured case.                                                              |
| (harness) | `vitest.config.ts` per Task 3 Step 1                                                                           | `astro check` does not know vitest's `test` field on `UserConfig` from `astro/config` (vitest 3.x no longer ambient-augments `vite`'s `UserConfig`). Fixed by excluding `vitest.config.ts` from the root `tsconfig.json` (`"exclude": ["dist", "vitest.config.ts"]`) rather than weakening the file's own types. |
