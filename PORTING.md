# Porting notes

One row per component where the Twig → Astro port needed a decision.

| Component            | Twig construct                                                                                                                                                                                                                                                                                   | Astro decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paragraph            | `{{- content -}}` (no `\|raw` in the twig, but the doc header types `content` as `[string,null]` HTML-bearing)                                                                                                                                                                                   | Rendered with `set:html` per R2's "content / html-bearing string props" rule, not a plain text child. No `allow_html` prop exists upstream, so none was added — the task brief's illustrative example included one that does not match the real Twig.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Paragraph            | `no_margin: [boolean,null]`                                                                                                                                                                                                                                                                      | Astro prop `noMargin?: boolean \| null`, default `false`; only appends `ct-paragraph--no-margin` when true. Not exercised by an upstream snapshot, so parity for this branch rests on the class-list logic mirroring the twig, not a captured case.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| (harness)            | `vitest.config.ts` per Task 3 Step 1                                                                                                                                                                                                                                                             | `astro check` does not know vitest's `test` field on `UserConfig` from `astro/config` (vitest 3.x no longer ambient-augments `vite`'s `UserConfig`). Fixed by excluding `vitest.config.ts` from the root `tsconfig.json` (`"exclude": ["dist", "vitest.config.ts"]`) rather than weakening the file's own types.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| (harness)            | Void/self-closing elements (`<img>`, `<br>`) not yet ported                                                                                                                                                                                                                                      | `normaliseHtml`'s `walk()` always emits a closing tag (`</${tag}>`). This is harmless today because both `actual` and `expected` go through the _same_ `walk()`, so the extra closing tag cancels out on both sides of the comparison — but a real DOM diff tool would show something different. Revisit when the first void-element component is ported.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| (harness)            | Upstream's `assertUniqueCssClasses(c)` (jest helper, checks the rendered class list has no duplicate tokens)                                                                                                                                                                                     | linkedom's parser doesn't error or warn on duplicate class tokens, and `normaliseHtml`'s class handling (`split` → `filter(Boolean)` → `sort` → `join`) silently de-duplicates nothing — a genuine duplicate class token would still appear twice in the sorted, joined string and would fail parity against upstream's (also duplicate-free) snapshot. There is no direct equivalent assertion in this harness; duplicate classes would only be caught if they change the compared string, which they do. No action needed, but noting there's no dedicated "no duplicate class" check, only the indirect one via string equality.                                                                                                                                                                         |
| (harness)            | HTML entities (`&amp;`, etc.) in snapshot or rendered content                                                                                                                                                                                                                                    | No special-case code: `linkedom`'s `parseHTML` decodes entities into `textContent` during parsing, so `&amp;` and a literal `&` both normalise to the same text node content. Confirmed by a self-test (`harness.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| (harness)            | linkedom `parseHTML('<body>…')` on a fragment                                                                                                                                                                                                                                                    | `parseHTML` requires a _complete_ document; handing it a bare `<body>...</body>` (or any fragment) string yields a `document` whose `body` is empty, silently dropping all content. Every call site (`normaliseHtml`, `unwrapSnapshotHtml`) wraps input in `<!DOCTYPE html><html><body>...</body></html>` before parsing — never pass a fragment straight to `parseHTML`.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| (harness)            | Whitespace collapse must never touch already-serialised markup                                                                                                                                                                                                                                   | `normaliseHtml`'s whitespace-collapse regex (`\s+` → ` `) runs only on raw _text node_ content, never on a joined-children string that contains child elements' serialised tags/attributes — running it there would also rewrite whitespace inside those children's attribute values. Per-element edge trimming (`.trim()` on the joined children) is stricter than plain rendered-text equivalence (it also discards meaningful edge whitespace a browser would keep in inline flow) — accepted by design; see the self-tests in `harness.test.ts` for the exact boundary.                                                                                                                                                                                                                                 |
| (harness)            | Jest's pretty-format DOM serializer renders ANY childless element self-closed (`<tag ... />`) as a display convention, even for non-void HTML tags like `<a>`                                                                                                                                    | Outside foreign content (svg/math), a trailing `/` before `>` on a non-void tag is not real self-closing syntax to an HTML parser — it is ignored, and the parser treats everything textually following as nested inside that (still-open) element until a real `</tag>` appears. First hit by `Menu`'s empty collapsible-trigger `<a></a>` (upstream: `renders collapsible menu`) sitting next to a following sibling `<div>`. Fixed generally in the harness: `upstreamSnapshot` now runs `fixNonVoidSelfClosingTags` (rewrites `<tag ... />` → `<tag ...></tag>` for any tag not in the standard void-element set) before parsing, so a `.snap` fixture's self-closed empty tags parse the same way a real browser parsed them the first time (as immediately-closed, not mis-nesting whatever follows). |
| Icon                 | `source(assets_dir ~ '/icons/' ~ symbol ~ '.svg', true)` then `source\|replace({'<svg ': '<svg ' ~ attr ~ ' '})\|raw`                                                                                                                                                                            | Replaced by the generated `icons.ts` symbol map (Task 2); `Icon.astro` looks up `icons[symbol]` and does the identical `'<svg '` → `'<svg ' + attrs + ' '` string replace so the injected attribute set (`class`, `aria-hidden`, `role`, then rest) lands in the same position upstream's Twig `replace()` puts it. Attribute order does not matter (the normaliser sorts attributes), only presence/values.                                                                                                                                                                                                                                                                                                                                                                                                |
| Datetime             | `{{ start_iso\|default(start)\|striptags }}`                                                                                                                                                                                                                                                     | `stripTags = (s) => s.replace(/<[^>]*>/g, '')` applied to `startIso ?? start` / `endIso ?? end` for the `datetime` attribute, while the visible `<time>` content keeps the original (possibly HTML-bearing) string via `set:html` — matches the "strips HTML tags from attribute values" snapshot, where the attribute is stripped but the rendered content is not.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Datetime             | `&mdash;` between start/end `<time>` elements, surrounded by Twig whitespace                                                                                                                                                                                                                     | Rendered as the literal `{' — '}` text node (with surrounding spaces) rather than an HTML entity — Astro does not decode `&mdash;` in plain template text, and the harness's entity-vs-literal-character equivalence only applies to text parsed from HTML strings, not to what Astro serializes as literal JS/JSX text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Grid                 | `template_column_count`/`auto_breakpoint` column-class algorithm (breakpoint map keyed 1,2,3,4,6, deliberately skipping 5, with a special-case skip at `template_column_count==6 && i==4`)                                                                                                       | Ported as a literal `for` loop over `1..validCount` replicating the same skip conditions, rather than a "clever" derived formula — the upstream algorithm's odd asymmetry (level skip at 6/4) is not obviously generalizable and a byte-for-byte translation is safer than a reinterpretation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Grid, ItemList, Menu | Sibling elements produced by a Twig `{% for %}` loop always have inter-element whitespace (from source newlines/indentation) that survives the harness's whitespace-collapse-per-text-node rule                                                                                                  | Astro's `items.map(...)` produces adjacent JSX elements with _no_ text node between them, which normalises to no separator at all — while upstream has a collapsed-to-one-space text node between siblings. Fixed by interleaving an explicit `{i > 0 && ' '}` text node between mapped siblings (columns, list items, menu items, and the sub-menu wrapper after a parent link) everywhere the Twig source loops. This is now a recognised pattern, not incidental.                                                                                                                                                                                                                                                                                                                                        |
| Grid                 | Three distinct "attributes" targets in one component (`attributes` → container-or-row, `row_attributes` → row always, `column_attributes` → column always)                                                                                                                                       | Modelled as three separate props (`...rest` for `attributes`, plus explicit `rowAttributes`/`columnAttributes` objects) rather than a single rest-spread, since R2's "attributes → rest spread onto root" assumes one root target; Grid's Twig has three. `rest` is applied to the container div when `useContainer`, or merged onto the row when not (mirrors `row_attributes.merge(attributes)`).                                                                                                                                                                                                                                                                                                                                                                                                         |
| Layout               | `content`, `content_top`, `content_bottom`, `sidebar_*` are plain Twig variables but are documented under a "Slots:" doc-header section                                                                                                                                                          | Translated to Astro named slots (`default` for `content`, camelCase names for the rest) per R2's slot rule, rather than string props — `Astro.slots.has(...)` stands in for Twig's `is not empty` gates. `hasSidebarLeft`/`hasSidebarRight` (and therefore `isContained`, `verticalSpacing`, and every `no-*-class`) are derived from slot presence, not a content string.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Menu                 | `{% import _self as menus %}` + two mutually-recursive macros (`menu_links`, `menu_links_below`) parameterised by `menu_level`                                                                                                                                                                   | Single recursive `Menu.astro` importing itself (`import Menu from './Menu.astro'`), branching on a `menuLevel` prop (0 → bare `<ul>`, `>0` → `<div class="...wrapper">` + nested `<ul>`) — mirrors the macro's own `{% if menu_level == 0 %}` branch instead of keeping two separate templates.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Menu                 | Upstream's per-level `aria_hidden`/`data-collapsible-panel` wrapper attributes read `item.in_active_trail` from the _enclosing_ `for` loop's `item` variable (a `_self`-import macro-scoping quirk — `item` is not a macro parameter), not from any property of the `below` items being rendered | Reproduced by passing an explicit `parentItem` prop down one recursion level (the parent item whose `.below` is being rendered), and reading `parentItem?.inActiveTrail` for the wrapper's `aria-hidden`, rather than relying on any implicit scoping (Astro components have no equivalent leaked-scope behaviour, nor should they).                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Menu                 | `@atoms/link/link.twig` include (01-atoms, out of this task's scope) for each menu item's link, which itself includes `@base/text-icon/text-icon.twig`                                                                                                                                           | Since `Link` is not ported until a later (01-atoms) task, the `<a class="ct-link ...">` wrapper is inlined directly in `Menu.astro` (its class list, `href`, `title`, and link attributes computed the same way `link.twig` computes them for the plain-text/no-icon/no-external case exercised by every Menu fixture) and its inner content delegates to the newly-ported `TextIcon.astro`, which upstream's `link.twig` also delegates to. Revisit this inlining once `Link` is ported — the two should converge instead of duplicating `ct-link` class logic.                                                                                                                                                                                                                                            |
| Menu                 | Empty `<a href="#" ...></a>` collapsible-trigger, immediately followed by a sibling `<div>`                                                                                                                                                                                                      | First component to have a genuinely-childless non-void element next to a following sibling — triggered the `fixNonVoidSelfClosingTags` harness fix documented above (Menu's `renders collapsible menu` snapshot is what surfaced it).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| TextIcon             | No upstream `.test.js` / `__snapshots__` for `text-icon`                                                                                                                                                                                                                                         | Given a smoke test only (root `.ct-text-icon__text` span), per the task brief's rule for components without an upstream test. Implemented the full Twig logic (icon placement, external-link icon, grouped last-word + icon, new-window visually-hidden text) as best-effort fidelity since `Menu` depends on TextIcon's simple (no-icon) branch for its own parity, but the icon/external/grouping branches are not snapshot-verified anywhere in this template.                                                                                                                                                                                                                                                                                                                                           |
| TextIcon             | `attributes` prop documented in the Twig doc header but never referenced anywhere in the Twig body                                                                                                                                                                                               | Accepted as a documented-but-intentionally-unused prop is not applicable here — no `attributes` prop was added to `Props` at all, since adding one and not using it would be a nonsensical API surface; the doc comment instead records that upstream itself never applies it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Grid                 | `row_attributes = row_attributes.merge(attributes)` (Drupal's `Attribute::merge()`, used only when `use_container` is false)                                                                                                                                                                     | Ported as a plain object spread, `{ ...rest, ...rowAttributes }` (`rowAttributes` wins on key collision). Drupal's `Attribute::merge()` has its own precedence/append rules (e.g. array-valued attributes like `class` are appended rather than replaced), which are not reproduced here — no upstream snapshot exercises `attributes` and `rowAttributes` sharing an overlapping key, so this divergence is undetected by parity today. Revisit if a future case needs Drupal's exact merge direction.                                                                                                                                                                                                                                                                                                     |
| (harness)            | `fixNonVoidSelfClosingTags`'s regex (`/<([a-zA-Z][a-zA-Z0-9-]*)((?:\s+[^<>]*?)?)\/>/g`)                                                                                                                                                                                                          | Assumes an attribute value never itself contains a literal `>` character — true of every `.snap` fixture pinned in this repo today, but a future upstream snapshot with e.g. a `title="a > b"`-style attribute value ahead of a self-closed non-void tag could confuse the attribute-capture group. Flagging rather than hardening against a case that cannot currently arise from any pinned fixture.                                                                                                                                                                                                                                                                                                                                                                                                      |
| Layout               | Seven Twig `{% block %}` markers (`content_top_block`, `content_block`, `sidebar_top_left_block`, `sidebar_top_right_block`, `sidebar_bottom_left_block`, `sidebar_bottom_right_block`, `content_bottom_block`)                                                                                  | Per R2, blocks render inline with no override mechanism in Astro — dropped. None of Layout's own upstream tests rely on a Drupal sub-theme overriding one of these blocks (they exist purely for downstream Drupal theme customisation), so no parity case is affected, but any future consumer expecting to override e.g. just the "content" section independently of the rest of Layout cannot do so with this port.                                                                                                                                                                                                                                                                                                                                                                                      |
| (harness)            | Two sibling elements with no rendered text between them, produced by *any* Twig construct (not only `{% for %}` loops — the pre-existing Grid/ItemList/Menu note) | Discovered while porting Button/Chip/ContentLink/FieldMessage/Fieldset, and traced back into `TextIcon` itself (the "icon before text", "grouped last word" and "isNewWindow visually-hidden span" branches — previously unverified against a real snapshot, since TextIcon has no upstream `.test.js`). Jest's pretty-format DOM plugin lays out sibling element nodes on separate indented lines in the `.snap` file regardless of whether a real whitespace text node separates them in the live DOM; parsing that `.snap` text back through the harness's `parseHTML` turns that formatting indentation into a genuine single-space text node. An Astro port with zero intervening text therefore always mismatches by exactly one space at that boundary. Fixed by adding an explicit `{' '}` between every pair of sibling elements/components that render with no text in between (TextIcon's before-icon/text-span, text-span/group-span and content/new-window-span boundaries; Checkbox's input/label; Chip's input/TextIcon; Fieldset's legend/wrapper and prefix/suffix; FieldMessage's icon/content) — the general form of the existing "sibling-separator" rule, now understood to apply to **any** two adjacent rendered elements, not only loop-generated ones. A pre-existing hand-authored fidelity test in `Menu.parity.test.ts` had hard-coded the (buggy, missing-space) TextIcon output; updated it to match once TextIcon was fixed.
| (harness)            | `checked="checked"` / `disabled="disabled"` literal-value boolean attributes in some `.snap` fixtures (Chip's `is_selected`, Button's `is_disabled`) vs. bare `checked`/`disabled` in others (Checkbox's `is_checked`) | Astro's own renderer (`htmlBooleanAttributes` regex in `astro/dist/runtime/server/render/util.js`, covering `checked`, `disabled`, `required`, `selected`, `multiple`, `readonly`, etc.) always emits these attributes bare when truthy, regardless of what string value a component passes — so an Astro port can never reproduce a fixture's literal `="disabled"`/`="checked"` text; only Twig, which runs outside Astro's renderer, can. Since presence alone conveys a boolean attribute's meaning to a browser (`checked`, `checked=""` and `checked="checked"` are exactly equivalent per the HTML spec), `normaliseHtml` now canonicalises every recognised HTML boolean attribute's value to `''` on both the actual and expected side before comparing (new `BOOLEAN_ATTRS` set in `harness.ts`, mirroring Astro's own list) — only presence is compared for these attributes, never their literal text. This is a harness-level fix, not a per-component one; it does not touch `aria-*` attributes (`aria-invalid`, `aria-disabled`, …), which are ordinary string-valued attributes and must still compare their literal `"true"`/`"false"` text.
| Button               | `kind` gates `<button>` / `<a role="button">` / `<input type="reset\|submit">`; `attributes` (rest) applies to whichever element renders                                                                          | Ported as a three-way ternary on the resolved `kind`, each branch spreading `...rest` on its own root element. `disabled` on the `<a>` branch needed a cast (`{...({ disabled: ... } as Record<string, unknown>)}` ) since Astro's `AnchorHTMLAttributes` type has no `disabled` field, even though upstream's `link.twig`-adjacent `button.twig` renders it there for the link kind. `button_content` (the `@base/text-icon/text-icon.twig` include) is delegated to the ported `TextIcon` component with `iconClass: 'ct-button__icon'`, per the task's fidelity rule.
| Checkbox, Fieldset   | `@atoms/label/label.twig` include (01-atoms, out of this task's scope)                                                                                                                                              | Inlined directly (mirroring Menu's precedent for `Link`) rather than imported. Checkbox's call site never passes `is_required`/`required_text`, so only the plain `tag: 'label'` case is reproduced there. Fieldset's call site *does* pass `is_required`/`required_text` through (tag: 'legend', size: 'large'), so the fuller branch (the `ct-label__required` span) is reproduced too, read directly off `label.twig` — not exercised by any upstream Fieldset snapshot (no test passes `legend` together with `isRequired`), so this branch's correctness rests on reading the Twig, not a captured case. Revisit both once `Label` is ported — they should converge on the real component instead of duplicating its class/markup logic twice.
| Chip                 | Upstream's test passes `is_disabled: true`, but `chip.twig` never reads an `is_disabled`/`disabled` variable anywhere in its body                                                                                   | No `isDisabled` prop was declared on `Chip`, per the fidelity rule that a declared prop must be read and rendered — a prop the markup ignores is not a real API surface. Confirmed by reading the full `chip.twig` source: no `is_disabled` reference exists.
| Chip                 | `attributes` (rest) target differs by `kind`: the inner `<input>` for `kind: 'input'`, but the outer `<a>`/`<span>` for `kind: 'link'`/`'default'`                                                                 | Modelled as `...rest` spread on whichever element is the real Twig target in each branch (three separate JSX spreads, one per branch), rather than a single rest spread on Chip's conceptual "root" — Grid's three-attributes-targets precedent (see the earlier Grid row) already established that R2's "attributes → rest spread onto the root element" assumes a single root, which does not hold here either.
| Fieldset             | `fields` documented under a "Slots:" doc-header section, but the twig body treats it as a plain HTML-bearing variable (`{{ fields }}`), and every upstream test passes it as a plain string prop                    | Ported as a `fields?: string` prop rendered with `set:html` (Paragraph's precedent), not an Astro named slot — the doc header's "Slots:" label is documentation-only here; twig has no `{% include %}`/slot mechanism for it, only a `{% block fields_block %}` wrapper (dropped per R2, no snapshot depends on overriding it).
| Iframe               | No `{% if %}` guard around the root `<iframe>` element (unlike every other atom in this task, which all gate on a required prop)                                                                                    | Ported as always-rendering (no conditional wrapper), matching upstream exactly — `url`, `width`, `height` are independently optional (each its own `{% if %}` around one attribute only).
| Image                | `alt` is rendered unconditionally (`alt="{{ alt }}"`, no `{% if %}` guard), including the `alt == '""'` Drupal literal-empty-string edge case                                                                       | `alt` always renders, defaulting to `''` — confirmed against the "renders with required attributes" snapshot, which has `alt=""` even though the test never passes an `alt` prop at all. The `'""'` (two-character literal) edge case is normalised to `''` before rendering.
